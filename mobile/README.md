# Trucker mobile

Expo (React Native) app for the Trucker API. Targets iOS; Android should work too.

## Screens

- **Today** – the active plan's exercises for today, pre-filled with target sets.
  Tick off sets as you do them, then *Finish workout*; only ticked sets are logged.
  The in-progress workout is saved on the device, so closing the app loses nothing.
- **Training plan** – create, edit and delete plans, and choose the active one.
  Each training day lists exercises with target sets and progression/deload rules.
- **History** – logged workouts; tap one for details, swipe left to delete it.
- **Progress** – estimated 1RM and volume per exercise.
- **Settings** – switch between the development and production server, and
  remove custom exercises. Every tab shows a DEV or PROD badge next to its
  title. Release builds always use production, with no switch or badge.
- **Rest timer** – ticking off a set starts it (or restarts it), counting up from
  0:00 to the target. It shows at the top of every screen in a Dynamic Island
  style: on a notched iPhone the notch grows to show the time, with the status
  bar hidden meanwhile. Tap it to expand it, with buttons to restart or stop;
  while idle, tap the notch to start it yourself. The target (3:00 by default)
  and what happens at the end – the island bursting open with a check and
  confetti, a vibration, both or neither – are set under Settings. Vibration uses a scheduled notification, so it also goes off with
  the phone locked. While it runs, the timer is also a Live Activity on the lock
  screen and in the real Dynamic Island, ticking without the app open and
  turning green with a check once the target is reached; it goes away when the
  timer is stopped or the app is opened after the end. Live Activities need a
  standalone build (not Expo Go) on iOS 16.2+, and can be turned off per app in
  iOS Settings.

## Running on your iPhone

Requires Node 20.19+ (`nvm use` picks up `.nvmrc`).

```sh
# terminal 1, repo root: the Go API on :8081
air

# terminal 2
cd mobile
npm install
npm start          # Metro on :8082 (8081 is taken by the API)
```

Install **Expo Go** from the App Store and scan the QR code with the Camera app.
The phone must be on the same Wi-Fi as your Mac. The app defaults to the API on
the machine running Metro (`http://<your-mac-ip>:8081`) as its development
server; change it under Settings, or set `EXPO_PUBLIC_API_URL` before
`npm start`. The production server defaults to `https://trucker.tail135e5e.ts.net`
(reachable over Tailscale); set `EXPO_PUBLIC_PROD_API_URL` to override it.
Dev builds start on the development server; release builds only use production.

## Standalone build (no Expo Go)

A release build embeds the JS bundle, so it runs without Metro. It is built
locally with Xcode; `ios/` is generated by `expo prebuild` and gitignored.

One-time setup:

1. Install Xcode from the App Store, then
   `sudo xcode-select -s /Applications/Xcode.app` and open it once.
2. Sign in with your Apple ID under Xcode → Settings → Accounts. With a free
   account the installed app expires after 7 days (rebuild to renew); a paid
   Apple Developer account makes that a year. Put your team ID in
   `ios.appleTeamId` in `app.json` so signing survives `--clean` prebuilds.
3. On the iPhone, turn on Developer Mode (Settings → Privacy & Security),
   connect it by USB and trust the Mac.

Then:

```sh
npm run prebuild:ios   # regenerate ios/ after changing app.json or native deps
npm run ios:release    # build, sign and install on the connected iPhone
```

Or do it all in one go with `npm run deploy:ios` (`scripts/deploy-ios.sh`): it
finds the connected iPhone, installs dependencies if needed, typechecks, runs
the prebuild when `app.json`, `app.config.ts` or `package.json` changed (or
with `--prebuild`), then builds and installs the release build. Pass a device
name or UDID to pick a specific phone.

Run `npm run ios:release` again after any JS change – there are no
over-the-air updates. The release build only talks to the production server
(`https://trucker.tail135e5e.ts.net`, or `EXPO_PUBLIC_PROD_API_URL` if set at
build time), so the phone must be on Tailscale; Settings shows the URL
read-only, with no development server. A release build only talks to HTTPS
servers.

The app has its own storage, separate from Expo Go, so pick the active plan
again on first launch. Logged workouts live on the server and are unaffected.
